# Build an isolated Cosmo voice lab

## Purpose / Big Picture

The active requirement, clarified on 2026-09-17, is a cascaded voice pipeline: speech-to-text (STT) converts microphone audio to words, a regular text language model (LLM) reasons and calls Murmur tools, and text-to-speech (TTS) streams the spoken answer. The user does not want a native speech-to-speech model such as Gemini Live or OpenAI Realtime. The intended experiment still uses Cosmo where its documented configuration supports this architecture. Streaming audio and WebRTC transport are compatible with this requirement; the restriction concerns the inference pipeline.

The existing `/labs/cosmo` implementation is an earlier native-audio prototype, not completion of that clarified requirement. A signed-in user can start a Cosmo conversation, see transcripts and microphone state, and use a temporary thought board and quadratic graph. A tool's completion means the browser has rendered its result. Preserve this isolated work as evidence and reusable authentication, lifecycle, transcript, and tool code while resolving Cosmo's cascaded configuration.

## Surprises & Discoveries

2026-09-17: Cosmo's [architecture guide](https://platform.askcosmo.ai/docs/architecture) explicitly describes modular STT -> LLM -> TTS selected via `model` and `model_options`. However, the [session-start contract](https://platform.askcosmo.ai/docs/reference/api/session-start) and installed SDK 0.6.0 expose realtime provider options and voice name/style without separate STT/LLM/TTS configuration. `model` is an arbitrary string, so that absence does not prove the backend cannot route to a cascade. A concrete model selector or configured catalog agent remains missing. Text-only output, custom microphone input, and a regular LLM called as a background tool do not establish the requested replacement pipeline.

The worktree already contains independent direct-provider profiles in `backend/murmur/voice/provider_profiles/livekit_cascade.py` and `pipecat_cascade.py`: Deepgram `nova-3`, Groq `openai/gpt-oss-120b`, and ElevenLabs `eleven_flash_v2_5`. These are local source facts, not evidence that the Cosmo account offers these providers or that those profiles are live-qualified in this worktree. Reuse their stage boundaries when a supported Cosmo contract is known; do not duplicate the concurrent voice-runtime work.

Murmur already has a Silero-backed browser hook (`web/src/hooks/use-vad.ts`) and an audio-based Smart Turn analyzer (`backend/murmur/voice/smart_turn.py`), but neither drives the Cosmo lab. The existing hook opens its own microphone and the legacy Smart Turn session assumes Deepgram transcript callbacks; these are reusable components with ownership adaptation, not drop-in Cosmo control. SDK 0.6.0 exposes custom audio input and a host-owned playback element, plus `sendActivityEnd()`, but its typed Gemini/OpenAI settings offer automatic detectors only and its public session has no explicit response cancellation/truncation. Confirm the current upstream contract before calling local playback muting a full turn-control implementation.
The user's asynchronous clarification identified premature answers as the primary complaint. It did not establish whether the new build had been tried. A baseline run with the earlier 900/4,000 ms configuration also held a 2.225-second synthetic pause, so that simple unfinished phrase does not reproduce the human problem. Tighten acceptance to require no assistant text or decoded audio until the entire continuation finishes, and add a complete-clause pause scenario that can plausibly be mistaken for the end of a request. The new 2,000/5,000 ms patient preset is a deliberate pacing adjustment, not a confirmed root-cause fix from this synthetic baseline.

The controlled interruption exposed a local transcript defect. Cosmo sent a user partial, completed the assistant turn (resetting its shared SDK turn ID), then sent the delayed cumulative user final. Our original `(role, turnId)` grouping duplicated that utterance and suppressed the next interruption as a late partial. Replaying the saved real wire sequence against SDK 0.6.0's own transcript reducer confirmed the fix: group each speaker's open bubble until its final, independently of shared turn IDs and role-dependent `append`. The SDK's normalized event comments and reducer documentation disagree on this point. New regression tests cover the real interleaving.

The first quadratic live attempt claimed a visible graph without rendering one; a second unchanged-build attempt invoked the tool and rendered correctly. A fast graph operation now uses a foreground tool that returns only after the SVG receipt; instructions require a successful tool result before a visibility claim. The second attempt also surfaced planning-style prose in the assistant transcript. Gemini now explicitly sets `includeThoughts: false`; this setting and prompt are mitigations, not proof that every future response will be correct.

Two controlled interruption attempts stopped the ongoing story and obeyed the changed request, with initial decoded-audio quiet windows around 0.8–0.9 seconds. These are not calibrated latency measurements. The first spoken prefix was absent from the captured wire; the probe previously could start on an audio-energy threshold without requiring the greeting's completed-turn marker. Tighten that wait, retain synthetic input timing, and require all request and interruption words in the final transcript before calling the pause scenario passed.

The user's first human session reached Cosmo but was told quadratic equations could not be shown. The lab's own prompt explicitly prohibited drawing and its only tools were text notes. This is an integration capability gap. The same session also exposed a conversational issue the synthetic single-turn smoke did not cover: early endpointing or missed barge-in. These are distinct controls and must be measured separately.

Merged main already includes `SVGCanvas.renderFunctionPlot` and deterministic mathematical-coordinate projection. The existing completing-square choreography compiler covers a restricted 36-equation family and currently depends on a separate model-backed stream. For this quadratic request, use the existing general graph renderer with bounded numeric coefficients and locally computed points, vertex, and real roots, keeping Gate 1.8's scene/reasoner work independent.
The local `main` branch is behind the merged scene work. The experiment therefore starts from fetched `origin/main`, not the active voice branch or local `main`.

The repository's `.agent/PLANS.md` still describes the deleted `funcs` tree. Current application code lives under `backend/murmur`; all changes and validation below use the actual layout.

Cosmo's SDK resolves a background tool after `ack` through `complete` or `fail`. Its JavaScript handler promises keep running after session teardown even though result delivery is closed. The lab must therefore own pending render acknowledgements and session generations, and must reject stale callbacks itself.

No Cosmo key was present in the existing checkout, ambient environment, or standard CLI credential location at the start. User authentication and provider readiness remain separate states in the lab.

The first live start returned HTTP 422 `invalid_tool_config`: Cosmo's restricted schema dialect forbids `additionalProperties`, even though plain TypeScript specs accept it. Removing that keyword fixed the rejection. Constructing tools through `cosmo-ai/tool` now validates the dialect locally.

SDK 0.6.0 supports `onSession`, which is required for events emitted before `start()` resolves. The adapter now subscribes there. Separately, a provider-free SDK reproduction confirmed that calling `end()` during a pending start POST can leave a late room and microphone unowned. The first SDK teardown must be deferred until startup settles; the lab retains call ownership and the ending state throughout. The SDK currently exposes no abort signal for a stalled startup POST.

## Context and Orientation

`backend/murmur/api/routers/__init__.py` composes FastAPI routes, and `backend/murmur/api/authentication.py` derives a trusted Murmur identity from a verified Firebase bearer token. `backend/murmur/core/config.py` reads the worktree's `.env`. The token broker will live in `backend/murmur/voice/cosmo.py`; the narrow HTTP interface will live in `backend/murmur/api/routers/cosmo_voice.py`.

`web/src/lib/firebase.ts` supplies Firebase bearer headers. `web/src/app/labs/cosmo/page.tsx` will expose the experiment, with UI and session behavior in `web/src/features/cosmo/`. A Cosmo session is one live provider connection with its own transcript and pending tools. A generation is the lab's local identity for one connection attempt; callbacks from old generations cannot change a newer call. A render acknowledgement means React has committed the thought card to the board; acceptance alone is not completion.

The request path is browser sign-in, authenticated Murmur token endpoint, server-to-server Cosmo mint request with the workspace key, and SDK connection using only the minted token. Missing authentication fails before minting. Disabled or unconfigured Cosmo fails with a fixed actionable response. Provider errors must not expose upstream bodies or credentials. Cross-origin requests remain governed by existing CORS configuration.
