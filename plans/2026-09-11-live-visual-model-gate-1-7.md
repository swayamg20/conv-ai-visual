# Teach projectile motion as one interruptible living visual model

## Purpose / Big Picture

Gate 1.7 turns Murmur from a verified visual lesson for one algebra family into a reusable live visual-model product. A signed-in learner opens `/canvas/projectile`, chooses an initial speed and launch angle, and watches one continuous projectile-motion explanation unfold: the launch velocity splits into horizontal and vertical components, the projectile traces a parabola, the board focuses the apex, and the same visual objects continue to impact and summary. The explanation must remain understandable with captions hidden. Equations, vectors, motion, labels, and spatial relationships carry the reasoning directly.

The learner can interrupt at a settled checkpoint and ask one of three high-value questions: why horizontal velocity stays constant, why acceleration is still downward when vertical velocity is zero at the apex, or why ascent and descent are symmetric in the no-drag model. The answer appears as a one-shot visual detour on the existing board, then the main explanation continues without a wipe or a restart. At any settled frontier, the learner can change to another supported launch speed or angle. Murmur preserves the semantic component and the identities of the axes, projectile, vectors, paths, apex, and range line while those objects morph to the new certified geometry. Dynamic value labels retain stable IDs but use the existing incompatible-content cross-fade, so text never snaps mid-glyph and retarget remains inside the patch-operation budget.

This gate proves a second visual domain, not a universal animation language. It adds one missing general motion capability—a verified path-trace cue with a marker that follows a fixed-topology path—and uses the existing immutable scene patches, checkpoint settlement, interruption, replay, authentication, and certificate-chain seams. The model, when explicitly selected as Director, may choose only a closed pedagogical action and stage. It may never produce physics, numbers, SVG, node identifiers, camera coordinates, timing, or integrity evidence. The primary Visual Reflex path is deterministic and provider-free.

The supported physical model is deliberately finite and explicit: ground-to-ground motion, metres and seconds, no drag or wind, zero launch height, and `g = 10 m/s²`. `speedMps` is one of 20, 25, or 30 and `angleDeg` is one of 30, 45, or 60, giving nine qualified problems. The compiler and an independently authored verifier separately derive `v_x = v_0 cos(theta)`, `v_y0 = v_0 sin(theta)`, `x(t) = v_x t`, `y(t) = v_y0 t - gt²/2`, time of flight, maximum height, range, trajectory samples, and the apex fact `v_y = 0` while `a_y = -g`. Inputs are hashed as exact integers. Displayed irrational values use one documented two-decimal half-up rule; mathematical checks use unrounded values.

The authored main lesson has six settled checkpoints: `setup`, `decompose_velocity`, `trace_ascent`, `apex_state`, `trace_descent`, and `summary`. Decomposition also establishes the two motion equations; summary settles impact, time, height, and range. This keeps every frontier pedagogically meaningful instead of manufacturing extra stops to match the previous gate. It targets 35 to 45 seconds at normal speed, has no unexplained hold longer than 1.2 seconds, and produces deterministic first meaningful visual feedback under 300 milliseconds locally. The exact pushed commit must preserve every Gate 1.4, 1.5, and 1.6 contract and fixture, pass a separate provider-free browser qualification, and produce reviewable video, board-only screenshots, and a commit-bound artifact manifest. A paid model call is neither required nor authorized for this gate.

## Surprises & Discoveries

- The existing low-level scene contract has lines, rectangles, text, LaTeX, and arbitrary paths, but the sealed choreography V1 can only enter, exit, transform, emphasize, and focus. A normal transform moves a projectile along the straight chord between endpoints; it cannot truthfully render curved flight. Gate 1.7 therefore needs an additive choreography V2 trace cue instead of overloading V1.
- Gate 1.6's `ParametricChoreographyStreamRuntime`, checkpoint contracts, and service are intentionally completing-square-specific. Their architectural pattern is reusable, but generalizing those large modules while adding a second domain would place two gates at risk. Gate 1.7 will share protocol-neutral players, renderers, and low-level contracts, while keeping a focused projectile service and runtime.
- Parameter retargeting changes the problem identity without changing the semantic component identity. The new certificate must bind both base and result problem hashes; Gate 1.6's single problem hash is insufficient for a legitimate morph.
- The current patch budget is per streamed response rather than per lifetime semantic revision. A six-checkpoint fresh lesson fits the existing cap with room for safe evolution, while a clarification or retarget is a separate one-checkpoint response and can still continue afterward.
- Fixed path topology is a powerful continuity seam. Sampling every supported ascent and descent with the same point count lets the browser morph trajectories without replacing their DOM identity and lets the verifier prove a marker remains on the certified curve.
- This isolated worktree's Python environment does not include the optional voice dependencies `livekit`, `loguru`, and `pipecat`, so an unfiltered `uv run pytest -q` stops during collection in seven voice-only modules. The 704-test visual-scene regression selection runs cleanly; the exact pushed-head CI environment remains the authoritative complete-suite check.
- Lexically sorted verifier snapshots and real browser `SceneState` order are different invariants. Clarification nodes are appended after retained nodes by patch application, so an unordered ID/value comparison would accept a different SVG paint stack under the same semantic frontier. Gate 1.7 therefore has a distinct patch-history scene materializer and requires exact ordered equality at continuation admission.
- A continuation service cannot treat an accepted certificate head as proof that the submitted browser scene is still canonical. Frontier admission now re-derives the entire visible model and its introduction order before routing, so a client cannot pair valid semantic metadata with a locally reordered or contaminated board.
- The Gate 1.6 runtime mixed reusable transactional mechanics with completing-square vocabulary in one large class. Moving only the mechanics behind a typed domain adapter reduced the old module substantially without changing its public surface or weakening its 1,003-test regression evidence.
- A fresh routed beat legitimately has no base problem, so its contract alone cannot prove that the router preserved the request's result problem. Service-level identity validation must explicitly bind `resolved.result_problem_spec` to the requested problem before lowering; otherwise a corrupted internal resolver can produce a fully self-consistent certificate for the wrong lesson.
- Literal annotations on plain dataclasses are not runtime validation. Director attempt ownership is now derived from the observed lifecycle boundary and checked with strict integer equality, preventing malformed internal results from poisoning browser event attempts or suppressing a terminal event.
- The shared choreography endpoint can remain additive without a new route: strict Pydantic protocol literals select three disjoint request families before admission, then one exhaustive runtime dispatch chooses the matching service and encoder. This keeps authentication, capacity control, cache headers, and upstream iterator ownership in one proven outer boundary.
- Browser verification can prove the syntax and mutual equality of all signed commitments without duplicating the backend's canonical JSON hashing implementation in synchronous client code. The browser therefore treats already joined SHA-256 artifacts as opaque commitments while independently checking every cleartext identity, revision, problem, patch, receipt, choreography, and chain relationship before playback.
- The old planner's lifecycle logic was reusable once checkpoint-specific certificate field names were normalized at the boundary. Keeping one internal planner avoided a second enter/exit/transform implementation and made the new `trace_path` exception explicit: its retained marker is updated by the trace cue, not silently counted as a normal transform.
- Replay evidence and bounded memory pull in the same direction: evicting an old checkpoint would make full zero-network Replay unverifiable, while an unbounded history would make a long exploration session unsafe. A 17-record Gate 1.7 envelope holds the complete lesson, every one-shot clarification, and one visit to each alternate problem before requiring an explicit Reset.
- The original stage was visually reusable but encoded completing-square semantics in its checkpoint vocabulary and corner flag. Passing already-derived labels, progress cardinality, and settled detail labels into a protocol-neutral shell preserves the exact old DOM while avoiding a second canvas/caption/quarantine implementation for projectile motion.
- The Next application does not enable imports from outside its application root, so backend-owned fixtures under `tests/fixtures` cannot be the browser qualification source. Gate 1.7 fixtures therefore live in a dedicated versioned directory beneath `web/src/features/live-scene/fixtures/`, while their Python generator and independent verifier remain backend-side and explicitly protect the sealed parent fixtures.
- An unclarified main continuation can reuse the untouched certified checkpoint suffix because each certificate already commits its exact prior frontier; only the outer stream generation and response-local sequence need a strict re-envelope. A clarification changes the semantic ledger and certificate head, so its continuation cannot reuse that suffix and must remain a separately compiled fixture lane.
- The production trajectory is a certified 33-point `M/L` polyline, not a cubic or quadratic SVG command. Curvature evidence must therefore measure non-collinearity and the certified sample geometry rather than search path text for `C` or `Q`.
- A page-level `locator("svg")` can also match nested control icons inside the canvas shell, even when those controls are visually hidden. Browser proof must select the direct board SVG rather than rely on SVG count or global document order.
- Authored visual duration in JSON does not prove that the review recording has the same duration. The WebM container must be independently decoded and timed before its manifest can claim the 35-to-45-second acceptance window.
- Raw SVG markup is not a cross-Replay oracle: RoughJS can emit different collinear cubic control points for the same zero-roughness line, and KaTeX internals are renderer representation rather than lesson semantics. Exact fixture proof therefore needs an independent semantic DOM projection, while raw markup remains useful only for detecting mutation during a two-second already-settled window.
- The evidence contract says four interruptions for each of six distinct surfaces—path trace, marker motion, vector morph, focus, equation morph, and hold. Combining path and marker into one category would weaken the written gate; qualification therefore requires 24 trials.
